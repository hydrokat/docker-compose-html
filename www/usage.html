Usage Guide

Learn how to develop, test, configure, and maintain static websites using the docker-compose-html architecture.

Prerequisites

Before launching the web service, confirm that your system has the following tools installed:

  • Docker Engine (v20.10+): The core container runtime.
  • Docker Compose (v2 plugin): The modern CLI plugin invoked via docker compose.
Terminal 
docker compose version

Quick Start

Spin up the Nginx web container with your static website files in seconds:

Terminal 
# 1. Clone the project repository
git clone git@github.com:hydrokat/docker-compose-html.git
cd docker-compose-html

# 2. Build image and start in background
docker compose up -d --build

# 3. Check container status
docker compose ps

Open http://localhost in your web browser. You will see the live website served by Nginx.

Stopping the Container

To stop the container gracefully:

Terminal 
docker compose down

Updating Content

This repository enforces an immutable image design. Rather than binding a host folder into the container using volumes, static assets are copied directly into the Docker image at build time (COPY www/ /usr/share/nginx/html/).

To update the site:

  1. Edit, add, or delete files inside the www/ directory.
  2. Rebuild and restart the container:
Terminal 
docker compose up -d --build
Why No Volumes?

Eliminating host volume mounts prevents permission mismatches between host users and the container's nginx user, eliminates file drift across environments, and guarantees that what you test locally is identical to production.

Port Configuration

The default docker-compose.yaml maps host ports 80 and 443 to container ports 80 and 443.

If your development machine already runs a web server (like Apache, Caddy, or another Docker container), you can remap host ports in docker-compose.yaml:

docker-compose.yaml 
services:
  web:
    build:
      context: .
      dockerfile: docker/nginx/Dockerfile
    ports:
      - "8080:80"    # Access via http://localhost:8080
      - "8443:443"   # Access via https://localhost:8443
    restart: unless-stopped

After editing the compose file, restart with docker compose up -d.

Enabling Local SSL

SSL/TLS is optional and can be activated directly by editing docker/nginx/nginx.conf.

Step 1: Generate a Local Certificate

Generate a local self-signed certificate using openssl into docker/nginx/certs/:

Terminal 
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout docker/nginx/certs/privkey.pem \
  -out docker/nginx/certs/fullchain.pem \
  -subj "/CN=localhost"

Step 2: Edit docker/nginx/nginx.conf

  1. Comment out the # BEGIN HTTP_STANDALONE block.
  2. Uncomment the # BEGIN SSL_REDIRECT block (redirects port 80 to 443).
  3. Uncomment the # BEGIN SSL_SERVER block (listens on 443 with SSL).

Step 3: Rebuild and Verify

Terminal 
docker compose up -d --build
curl -kfsS https://localhost/
Private Key Security Warning

Because there are no volumes, certificate files in docker/nginx/certs/ are copied into the Docker image at build time. Private keys must never be committed to Git (they are gitignored) and images containing keys must never be pushed to public image registries.

Testing & Verification

An automated smoke testing script is provided in tests/smoke.sh. It performs end-to-end verification of compose syntax, container boot, Nginx configuration syntax, HTTP serving, 404 error handling, and optional SSL.

Terminal 
# Test HTTP standalone mode
./tests/smoke.sh

# Test full SSL lifecycle (generates cert, validates HTTPS & 301, tears down)
SMOKE_SSL=1 ./tests/smoke.sh

Troubleshooting

Port Already Allocated

If you see Bind for 0.0.0.0:80 failed: port is already allocated, find the process holding the port:

Terminal 
lsof -i :80
docker ps

Either stop the conflicting service or remap the host port in docker-compose.yaml.

Verifying Nginx Configuration Inside Container

If the container fails to start or restarts unexpectedly, test the Nginx configuration syntax:

Terminal 
docker compose exec web nginx -t

Inspecting Container Logs

Follow live server access and error logs:

Terminal 
docker compose logs -f web
