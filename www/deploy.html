VPS Deployment Guide

A step-by-step production deployment guide for launching static websites with docker-compose-html on any cloud VPS (DigitalOcean, Hetzner, Linode, Vultr, AWS Lightsail) running Ubuntu 24.04 LTS.

Standard Assumptions

This guide assumes an Ubuntu 24.04 LTS instance, your domain is example.com, and you have root SSH access to begin. Replace example.com with your registered domain.

1. DNS & Domain Setup

Before configuring certificates, configure your domain's DNS records at your registrar or DNS host (Cloudflare, Namecheap, Route53):

  • A record: example.com → YOUR_VPS_IP_ADDRESS
  • A record (or CNAME): www.example.com → YOUR_VPS_IP_ADDRESS (or example.com)

Verify global DNS propagation from your local terminal before proceeding:

Terminal 
# Check that the returned IP matches your server
dig +short example.com
dig +short www.example.com

2. Server Hardening

Connect to your new VPS and establish a secure baseline with a non-root administrative user and firewall:

Create a Dedicated Sudo User

Terminal 
# Add a non-root deployer user
adduser deployer
usermod -aG sudo deployer

# Copy SSH keys to the new user
mkdir -p /home/deployer/.ssh
cp /root/.ssh/authorized_keys /home/deployer/.ssh/
chown -R deployer:deployer /home/deployer/.ssh
chmod 700 /home/deployer/.ssh
chmod 600 /home/deployer/.ssh/authorized_keys

Harden SSH Configuration

Disable remote root login and password authentication in /etc/ssh/sshd_config.d/99-hardened.conf:

Terminal 
sudo tee /etc/ssh/sshd_config.d/99-hardened.conf << 'EOF'
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
X11Forwarding no
EOF

sudo systemctl restart ssh

Configure UFW Firewall

Allow only SSH, HTTP, and HTTPS traffic:

Terminal 
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo ufw status verbose

3. Install Docker Engine & Compose

Install the official Docker Engine and Docker Compose v2 plugin from the official Docker apt repository:

Terminal 
# Update package list and install prerequisites
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# Add Docker's official GPG signing key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Set up the stable repository
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine and plugins
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Enable and start Docker service
sudo systemctl enable --now docker

# Optional: Add deployer user to docker group (grants root-equivalent Docker control)
sudo usermod -aG docker deployer

4. Deploy Repository

Deploy the website codebase to /opt/site:

Terminal 
# Create target directory with correct ownership
sudo mkdir -p /opt/site
sudo chown deployer:deployer /opt/site

# Clone repository
git clone git@github.com:hydrokat/docker-compose-html.git /opt/site
cd /opt/site

# Start HTTP web container
docker compose up -d --build

Verify by visiting http://example.com in your browser. Nginx should serve the site over HTTP.

5. Production HTTPS with Let's Encrypt

Secure your website with a free, trusted SSL/TLS certificate from Let's Encrypt.

Install Certbot

Terminal 
sudo apt-get install -y certbot

Obtain Certificate via Standalone ACME

Temporarily shut down the Nginx container so Certbot can bind to port 80 to complete the HTTP-01 challenge:

Terminal 
cd /opt/site
docker compose down

sudo certbot certonly --standalone \
  -d example.com \
  -d www.example.com \
  --agree-tos \
  --email admin@example.com \
  --non-interactive

Copy Certificates to Build Context

Terminal 
# Copy issued certificates into docker/nginx/certs/
sudo cp /etc/letsencrypt/live/example.com/fullchain.pem /opt/site/docker/nginx/certs/
sudo cp /etc/letsencrypt/live/example.com/privkey.pem /opt/site/docker/nginx/certs/

# Restrict permissions
sudo chown deployer:deployer /opt/site/docker/nginx/certs/*.pem
chmod 644 /opt/site/docker/nginx/certs/fullchain.pem
chmod 600 /opt/site/docker/nginx/certs/privkey.pem

Enable SSL in docker/nginx/nginx.conf

  1. Open docker/nginx/nginx.conf.
  2. Comment out the # BEGIN HTTP_STANDALONE server block.
  3. Uncomment the # BEGIN SSL_REDIRECT block and set server_name example.com www.example.com;.
  4. Uncomment the # BEGIN SSL_SERVER block and set server_name example.com www.example.com;.

Rebuild & Launch HTTPS

Terminal 
docker compose up -d --build
curl -fsS https://example.com/

6. Automated Certificate Renewal

Because static files and certificates are baked directly into the Docker image, renewing certificates requires:

  1. Stopping Nginx to release port 80 during renewal.
  2. Renewing the certificate with Certbot.
  3. Copying the new .pem files into docker/nginx/certs/.
  4. Rebuilding and restarting the Docker container.

Create a dedicated renewal deploy hook script at /etc/letsencrypt/renewal-hooks/deploy/update-site.sh:

/etc/letsencrypt/renewal-hooks/deploy/update-site.sh 
#!/usr/bin/env bash
set -euo pipefail

SITE_DIR="/opt/site"
DOMAIN="example.com"

echo "==> Deploying renewed certificates for $DOMAIN"
cp "/etc/letsencrypt/live/$DOMAIN/fullchain.pem" "$SITE_DIR/docker/nginx/certs/"
cp "/etc/letsencrypt/live/$DOMAIN/privkey.pem" "$SITE_DIR/docker/nginx/certs/"
chmod 644 "$SITE_DIR/docker/nginx/certs/fullchain.pem"
chmod 600 "$SITE_DIR/docker/nginx/certs/privkey.pem"

echo "==> Rebuilding Docker container with fresh certificate"
docker compose -f "$SITE_DIR/docker-compose.yaml" up -d --build

Make the script executable and test the renewal pipeline with a dry run:

Terminal 
sudo chmod +x /etc/letsencrypt/renewal-hooks/deploy/update-site.sh

# Run dry run with pre-hook to stop docker during port 80 challenge
sudo certbot renew --dry-run --pre-hook "docker compose -f /opt/site/docker-compose.yaml down"

Certbot's built-in systemd timer (systemctl status certbot.timer) will now run automatically twice daily.

7. Zero-Downtime Updates & Rollbacks

Deploying website updates or rolling back is fast and deterministic:

Deploying Changes

Terminal 
cd /opt/site
git pull origin trunk
docker compose up -d --build

Rolling Back to a Previous Version

If an update causes an issue, roll back instantly using git commit history:

Terminal 
cd /opt/site
git checkout <PREVIOUS_COMMIT_SHA>
docker compose up -d --build

8. Server Maintenance & Operations

Automatic Service Restarts

The compose definition includes restart: unless-stopped. If the VPS reboots (e.g., after kernel security patches), systemd automatically brings Docker and your website container back online.

Cleaning Unused Docker Images

As you rebuild images with content updates, remove dangling image layers to conserve disk space:

Terminal 
# Remove dangling unused images
docker image prune -f

Backup Strategy

Because static HTML and server configuration live in Git, your codebase is already version-controlled. Only back up:

  • Let's Encrypt directory: /etc/letsencrypt
  • Server configuration: /etc/ssh, /etc/ufw

9. Production Security Checklist

Review this checklist before announcing your live website:

  • ☑ SSH key authentication active; root and password SSH disabled.
  • ☑ UFW firewall active, allowing only ports 22, 80, and 443.
  • ☑ Valid SSL certificate installed with automatic HTTP-to-HTTPS 301 redirect.
  • ☑ server_tokens off enabled in Nginx (hides Nginx version).
  • ☑ Hardened HTTP security headers (X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Content-Security-Policy) active.
  • ☑ Private keys in docker/nginx/certs/ are gitignored and never committed.
  • ☑ Built Docker images containing private keys are never pushed to public registries.
  • ☑ Certbot renewal hook dry-run validated.
